# 완성 예시 (통째로 베껴 시작하기)

처음이라면 아래를 복사해서 이름·내용만 바꿔 시작하세요.

## 예시 1 — 가장 단순한 스킬 (SKILL.md 하나)

폴더 `weekly-report/` 안에 `SKILL.md`:

```markdown
---
name: weekly-report
description: >-
  한 주 업무를 정해진 형식의 주간보고로 정리하는 스킬. "주간보고 써줘", "이번 주 한 일
  정리", "위클리 리포트" 같은 요청에서 켜진다. 사용자가 메모·불릿을 던지면 아래 형식으로
  다듬어 준다.
---

# 주간보고 작성

사용자가 준 메모를 아래 형식으로 정리하라. 없는 항목은 지어내지 말고 "해당 없음"으로 둔다.

## 형식
# [이름] 주간보고 (YYYY-MM-DD ~ YYYY-MM-DD)
## 이번 주 완료
- (핵심 성과 위주, 3~5개)
## 진행 중
- (현황 % 또는 상태)
## 다음 주 계획
- (우선순위 순)
## 이슈·도움 필요
- (막힌 것, 필요한 결정)

## 원칙
- 사실만 적는다(과장 금지). 성과는 "무엇을 → 어떤 결과"로 쓴다.
- 한 줄은 간결하게. 판단이 필요한 애매한 항목은 사용자에게 먼저 물어라.
```

## 예시 2 — 참고파일로 나눈 스킬

```
contract-review/
├── SKILL.md
└── references/
    ├── toxic-clauses.md
    └── checklist.md
```

`SKILL.md`:

```markdown
---
name: contract-review
description: >-
  계약서를 7대 필수조항·독소조항 기준으로 검토하는 스킬. "계약서 봐줘", "독소조항 찾아줘",
  "이 계약 위험한 데 없어?" 같은 요청에서 켜진다.
---

# 계약서 검토

## 흐름
1. 계약서 전문을 읽고 당사자·목적·기간·금액을 먼저 요약한다.
2. 독소조항을 점검한다 → references/toxic-clauses.md
3. 최종 체크리스트로 빠진 조항을 확인한다 → references/checklist.md
4. 발견을 "위험도(상/중/하) + 근거 + 수정 제안" 표로 정리한다.

## 원칙
- 법 조문을 인용할 땐 지어내지 말고 확인된 것만. (법령 MCP가 있으면 그것으로 확인)
- 최종 판단은 사용자·전문가의 몫임을 밝힌다.
```

## 예시 3 — MCP를 쓰는 스킬 (법령 검색 연동)

```markdown
---
name: law-checker
description: >-
  한국 법령을 실제 조문으로 확인해 인용하는 스킬. "이거 무슨 법 위반이야?", "약관규제법
  몇 조야?", "관련 법 조문 찾아줘" 같은 요청에서 켜진다. 법 조문은 추측하지 않고 반드시
  도구로 확인한다.
---

# 법령 확인

## 사전 조건
korean-law MCP가 필요하다. 없으면 mcp__mcp-registry__search_mcp_registry 로 "법령/law"
커넥터를 찾아 사용자에게 연결을 제안하고, 연결 전에는 인용을 진행하지 않는다.

## 절차
1. mcp__korean-law__search_law 로 관련 법을 검색한다.
2. mcp__korean-law__get_law_text 로 조문 원문을 가져온다.
3. "법령명 제○조 (조회일자 YYYY-MM-DD)" 형식으로 인용한다.

## 원칙
- 조문 번호·내용을 절대 지어내지 않는다. 도구로 확인한 것만 인용한다.
- 이건 참고용이며 법적 자문이 아님을 밝힌다.
```

## 시작 요령

1. 위에서 목적에 가까운 걸 하나 골라 폴더째 복사.
2. `name`과 `description`부터 내 상황에 맞게 고침(트리거 문구 구체적으로).
3. 본문을 내 작업 방식대로 수정.
4. `packaging.md`대로 `.skill`로 묶어 설치·테스트.
