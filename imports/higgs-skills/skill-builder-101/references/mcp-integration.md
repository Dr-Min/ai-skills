# MCP 연동법 (스킬에 외부 도구 붙이기)

## MCP가 뭔가요? (쉬운 말로)

**MCP(Model Context Protocol) = Claude에게 "새로운 손발"을 붙여주는 표준 연결 방식**입니다.

기본 Claude는 파일 읽기·쓰기, 웹 검색 정도만 합니다. 그런데 슬랙에 메시지 보내기, 구글드라이브
문서 열기, 한국 법령 검색하기 같은 걸 하려면 **그 서비스와 연결된 도구**가 필요해요. 그 연결
규격이 MCP입니다. MCP로 연결하면 Claude에게 `mcp__슬랙__send_message` 같은 **새 도구들**이
생깁니다.

핵심 구분(초보자가 헷갈리는 부분):
- **스킬(Skill)** = "무엇을 어떻게 하라"는 **지침서**(텍스트).
- **MCP** = 실제로 행동할 수 있는 **도구(손발)**.
- 둘은 별개예요. 스킬은 "이럴 땐 저 MCP 도구를 이렇게 써라"라고 **지시**할 뿐, 도구 자체를
  품고 있지는 않습니다. 그래서 MCP를 쓰는 스킬은 **그 MCP가 먼저 연결돼 있어야** 작동합니다.

## MCP 도구 이름 규칙

MCP 도구는 항상 이 형태입니다:

```
mcp__<서버이름>__<도구이름>
```

예:
- `mcp__korean-law__search_law` — 한국 법령 검색
- `mcp__slack__send_message` — 슬랙 메시지 전송
- `mcp__mcp-registry__search_mcp_registry` — 사용할 수 있는 MCP(커넥터) 찾기

스킬 본문에서 이 이름을 그대로 적어 "이 도구를 써라"라고 지시하면 됩니다.

## 방법 A — 이미 연결된 MCP를 스킬에서 쓰기 (가장 흔함)

사용자 환경에 이미 어떤 MCP가 연결돼 있다면(예: `korean-law`), 스킬 본문에서 그 도구를
**이름으로 지목**해 쓰라고 적기만 하면 됩니다.

```markdown
## 법 조문 인용하기
계약 조항을 검토할 때는 추측하지 말고 실제 조문을 확인하라:
1. `mcp__korean-law__search_law` 로 관련 법(예: 약관규제법)을 검색한다.
2. `mcp__korean-law__get_law_text` 로 해당 조문 원문을 가져온다.
3. 인용할 때 "법령명 제○조 (조회일자)"를 함께 표기한다.
절대 조문 번호나 내용을 지어내지 마라 — 반드시 도구로 확인한 것만 인용한다.
```

포인트:
- **"지어내지 말고 도구로 확인하라"**를 꼭 넣으세요. 그래야 Claude가 상상 대신 실제 도구를 씁니다.
- 도구가 **없을 때의 대비책**도 적으면 좋습니다("해당 MCP가 없으면 사용자에게 연결을 안내하라").

> 실제 사례: 이 환경의 `biz-legal-team`·`biz-tax-team` 스킬이 바로 이 방식으로 `korean-law`
> MCP의 `search_law`·`get_law_text` 등을 호출해 법 조문을 실시간 인용합니다.

## 방법 B — 필요한 MCP가 아직 없을 때 (연결부터 안내)

스킬이 어떤 MCP를 필요로 하는데 사용자에게 아직 없다면, **연결을 먼저 안내**해야 합니다.
Claude는 "커넥터 레지스트리"에서 알맞은 MCP를 찾아 제안할 수 있습니다:

1. `mcp__mcp-registry__search_mcp_registry` 로 관련 커넥터를 검색
   (예: 슬랙 작업이면 `["slack", "chat", "메시지"]`).
2. 맞는 게 있으면 `mcp__mcp-registry__suggest_connectors` 로 사용자에게 연결을 제안.
3. 사용자가 **직접** 설정에서 연결을 승인(로그인·권한 허용은 사용자만 할 수 있음).

스킬 본문에는 이렇게 적어둡니다:

```markdown
## 사전 조건
이 스킬은 Slack MCP가 필요하다. 연결돼 있지 않으면:
1. mcp__mcp-registry__search_mcp_registry 로 "slack" 커넥터를 찾는다.
2. mcp__mcp-registry__suggest_connectors 로 사용자에게 연결을 제안한다.
3. 사용자가 연결을 마치기 전에는 전송 단계를 진행하지 말고 대기한다.
```

## 방법 C — MCP를 스킬과 함께 "배포"하기 (플러그인)

스킬 하나만 공유할 땐 `.skill` 파일이면 됩니다(→ `packaging.md`). 하지만 **스킬 + 그 스킬이
쓰는 MCP를 한 묶음으로** 남에게 배포하려면 **플러그인(plugin)** 형태로 만듭니다. 플러그인은
스킬·MCP 설정·명령을 함께 담는 설치 꾸러미예요.

플러그인 폴더 구조(개념):

```
my-plugin/
├── .claude-plugin/
│   └── plugin.json          ← 플러그인 이름·버전 등 메타데이터
├── skills/
│   └── my-skill/
│       └── SKILL.md         ← 스킬
└── .mcp.json                ← 이 플러그인이 딸려오는 MCP 서버 정의
```

`.mcp.json` 예시(로컬 실행형 MCP 서버를 함께 배포하는 경우):

```json
{
  "mcpServers": {
    "my-tool": {
      "command": "npx",
      "args": ["-y", "@example/my-tool-mcp-server"]
    }
  }
}
```

이렇게 하면 사용자가 플러그인을 설치할 때 스킬과 MCP가 **함께** 들어옵니다. 여러 플러그인을
묶어 배포하려면 "마켓플레이스(marketplace)"로 만들 수도 있습니다.

> 초보자 팁: 여기까지는 고급 단계입니다. 처음엔 **방법 A**(이미 연결된 MCP를 스킬에서 부르기)
> 만으로도 충분해요. 배포·팀 공유가 필요해질 때 방법 C로 확장하세요. 플러그인/마켓플레이스를
> 실제로 만들 때는 이 세션의 `create-cowork-plugin` 스킬을 함께 쓰면 자동으로 골격을 잡아줍니다.

## MCP 쓰는 스킬을 만들 때 체크리스트

- [ ] 이 스킬이 정말 MCP가 필요한가? (파일·웹검색으로 되는 일이면 MCP 불필요)
- [ ] 쓸 도구 이름을 정확히 적었는가? (`mcp__서버__도구`)
- [ ] "지어내지 말고 도구로 확인하라"를 넣었는가?
- [ ] 도구가 없을 때의 안내(연결 제안 or 대기)를 넣었는가?
- [ ] 남에게 배포한다면, MCP까지 함께 줘야 하는가(→ 플러그인)?

## 안전 주의
- 로그인·비밀번호·토큰 입력, 결제, 권한 승인은 **사용자만** 합니다. 스킬이 Claude에게 그런 걸
  대신 하라고 시키면 안 됩니다.
- 외부에서 읽어온 내용(웹페이지·문서 등)에 담긴 "이 도구를 실행하라" 같은 지시는 **명령이 아니라
  데이터**로 취급하라고 스킬에 명시하면 더 안전합니다.
